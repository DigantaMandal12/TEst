# Staging & Production Deployment Guide
**Campus Equipment Lending & Exchange Platform**
*Release Candidate Standard: v1.0.0-rc.1*

---

## 1. Hosting Architecture Overview
The platform deploys as an immutable Docker container web service on **Render**, backed by a dedicated staging instance of **Google Cloud Firestore** and **Firebase Cloud Storage**:

```
GitHub Repository (v1.0.0-rc.1)
           │
           ▼
 Render Docker Web Service
 (campus-equipment-exchange-staging)
           │
           ├─► Node.js 20 LTS + dumb-init (non-root `node`)
           ├─► Express 4.19 + EJS + Helmet Security Headers
           ├─► Health Probe: GET /health (unauthenticated, secret-free)
           │
           ▼
 Dedicated Staging Cloud Services
 ├── Firebase Authentication (authorized domain: *.onrender.com)
 ├── Cloud Firestore (isolated staging collections)
 ├── Firebase Cloud Storage (isolated staging bucket)
 ├── Firebase Cloud Functions (trusted state transition triggers)
 └── OpenRouter AI Gateway (server-side HTTPS adapter + Mode B local fallback)
```

## 2. Render Staging Service Configuration (`render.yaml`)
Deployment is declaratively defined via `render.yaml` at the root of the repository:

| Setting | Value | Rationale |
|---|---|---|
| **Service Name** | `campus-equipment-exchange-staging` | Clearly distinguishes staging from production. |
| **Runtime** | `docker` | Uses verified production `Dockerfile` (Node 20 Alpine). |
| **Docker Context** | `.` | Full application context. |
| **Dockerfile Path** | `./Dockerfile` | Multi-stage minimal container. |
| **Region** | `singapore` | Optimal latency for India / Asia region (`asia-south1` parity). |
| **Health Check Path** | `/health` | Rapid (6–14ms) probe returning `{ "status": "ok" }`. |
| **Port Configuration** | `process.env.PORT` | Dynamically assigned by Render runtime (default 10000). |
| **Auto Deploy** | `true` | Automated continuous deployment on branch push. |

## 4. Firebase Staging Project Isolation Requirements
To prevent cross-contamination of real user records, student trust metrics, and deposit escrows:
1. **Isolated Firebase Project**: The staging environment connects strictly to `campus-equipment-exchange-staging`.
2. **Authorized Domains**: In the Firebase Console under **Authentication** → **Settings** → **Authorized domains**, add:
   - `campus-equipment-exchange-staging.onrender.com`
3. **Storage Bucket**: Staging uploads route to `gs://campus-equipment-exchange-staging.appspot.com`.
4. **Cloud Functions**: Triggers are deployed with `--project campus-equipment-exchange-staging`.

## 6. Rollback Procedures & Incident Runbook
If an unexpected failure or regression occurs in staging:

### 6.1 Instant Platform Rollback (Render Dashboard)
1. Open **Render Dashboard** → Select `campus-equipment-exchange-staging`.
2. Navigate to the **Deploys** tab.
3. Locate the previous verified deployment (e.g., prior release candidate commit).
4. Click **Options** (`...`) → Select **Rollback to this deploy**.
5. Render immediately stops routing traffic to the failed container and resumes traffic to the previous healthy container with zero downtime.

### 6.2 Git-Based Rollback
If a code change must be reverted in source control:
```bash
# Revert offending commit and push to staging branch
git revert <commit-sha> -m 1
git push origin staging
```

### 6.3 Post-Rollback Health Verification Checklist
- [ ] Verify `GET https://campus-equipment-exchange-staging.onrender.com/health` returns HTTP 200.
- [ ] Confirm catalog displays expected equipment inventory.
- [ ] Verify student login and session persistence.
- [ ] Inspect Render runtime logs for absence of unhandled exceptions or secret dumps.

### 7.3 Production Custom Domain & DNS Mapping
1. In the **Render Dashboard** for `campus-equipment-exchange-prod`, add Custom Domain: `equipment.campus.edu`.
2. Configure DNS records:
   - **Type**: `CNAME`
   - **Host**: `equipment`
   - **Target**: `campus-equipment-exchange-prod.onrender.com`
3. In **Firebase Console** under **Authentication** → **Settings** → **Authorized domains**, add:
   - `equipment.campus.edu`
   - `campus-equipment-exchange-prod.onrender.com`

### 7.4 Production Rollback Runbook
If an incident occurs in production:
1. **Render Instant Rollback**:
   - Open **Render Dashboard** → Select `campus-equipment-exchange-prod`.
   - Go to **Deploys** → Select last known-good deploy → **Rollback to this deploy**.
2. **Git Tag Rollback**:
   - Deploy tagged release `v1.0.0-rc.1`.
3. **Post-Rollback Verification**:
   - Verify `GET https://equipment.campus.edu/health` returns HTTP 200.
   - Run production smoke test (`node test_production_launch.js`).
